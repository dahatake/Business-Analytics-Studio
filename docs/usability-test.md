# 利用テストの計画（F-3.4.2）

F-3.4.2 の受け入れの観点は「対象者・操作課題・成功率・所要時間を定めた利用テストで検証する。具体値は第 11.7 節で合意する」です。合意前のため、ここでは **提案値** を置きます。値は `src/config/params.ts` の `usabilityTaskSuccessRateTarget` と `usabilityTaskTimeTargetSec` にあり、合意後はそこだけを変えます。

人による利用テストはまだ実施していません。自動テストでは「操作課題を最後まで実行できること」だけを確かめています（`e2e/visuals.spec.ts`・`e2e/interaction.spec.ts`）。

## 対象者（提案）

- 要求定義書 §4 の「事業企画担当」「業務改善リーダー」「経営層・意思決定者」から各 2 名以上、合計 5〜8 名
- 本アプリを初めて使う人。事前の説明は 1 分以内で、画面の「使い方」パネルの内容に限る

## 操作課題（最適化画面）

| # | 課題 | 成功の判定 |
|---|---|---|
| T1 | 需要を +5%、炭素価格を 20,000 円/t-CO2 にして最適化を実行する | サマリーの「適用した前提」が一致する |
| T2 | 最適化前と後で、総コストがいくら下がったかを答える | 元の数値の表の値と ±0.1 百万円以内で一致 |
| T3 | 最適化前に生産能力を超える工場があるかを答える | 容量レポートの警告と一致 |
| T4 | 需要を +15% にしたとき、なぜ配分できないかを説明する | 「需要が生産能力を超える」旨を答える |
| T5 | 社外向け表示に切り替え、案件の金額が見えないことを確認する | 金額が「非表示」になっていると答える |

## 指標と目標（提案値）

| 指標 | 定義 | 目標（提案） |
|---|---|---|
| 成功率 | 成功した試行 ÷ 全試行 | 80% 以上 |
| 所要時間 | 課題の提示から回答までの中央値 | 90 秒以内（課題ごと） |
| 補助の回数 | 進行役が口頭で助けた回数 | 0 回を目標。記録だけ行う |

## 記録の方法

- 画面の録画（音声なし）と、課題ごとの開始・終了時刻
- 終了後に SUS（System Usability Scale）を記入してもらう（参考値。合否には使わない）
- 結果は `docs/usability-results/<日付>.md` に、課題ごとの成功・時間・つまずいた画面要素を残す
