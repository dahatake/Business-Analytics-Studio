# 測定と確認の手順（D-8、種類 C のタスク）

[判断資料](decision-guide.md) の D-8（P-04 と追加 2 点、2026-11-09 承認）に従って、人と実機でしか確かめられない残タスクを行う手順です。ヘッドレスやソフトウェア描画、スタブ・モックでの結果は**達成の証拠にしません**（Q-121 の回答）。

## 共通の条件

| 項目 | 内容 |
|---|---|
| 基準端末 | 利用者が指定する 1 台に固定します。CPU・GPU・メモリ・OS・ブラウザーの版・表示解像度（4K）・電源設定・回線を記録します（測定の道具が環境を自動で記録します） |
| 測定中の負荷 | **他の処理を動かしません。** E2E や他のアプリを止めます（2026-11-09 に、並列の E2E と同時に流すと合否が変わることを確認済み） |
| 試行数 | 条件ごとに本試行 10 回と、最初のウォームアップ 1 回（集計から除く） |
| 集計 | p50 と最大値。外れ値は除きません |
| 証跡 | 生の時刻ログ、環境の記録、測定したコミット、画面の録画、送信先と呼び出し回数 |

## M-1. KPI-1（顧客パックの生成から起動まで）

前提: C-03 の `packBuild` の行が許可されていることです。現在は段階的な許可の第 1 行（`explain`）だけが許可されているため、**実接続での測定はまだ行えません**。それまでは決定的な生成で道具の動作だけを確かめます。

```powershell
npm run bas -- research <顧客名>
for ($i = 0; $i -lt 11; $i++) { npm run bas -- build <顧客名>; npm run bas -- launch <顧客名> }   # 起動後は Ctrl+C
npm run kpi1 -- <顧客名>     # build + launch を 1 回分として、p50 と最大値を PARAM-001（6 分）・PARAM-002（中央値 4 分）と比べる
```

## M-2. 4K・60 fps（KPI-5）と、移動・リサイズ中の 30 fps（PARAM-065）

```powershell
npm run build
npm run measure -- --headed       # 4K の表示装置を持つ基準端末で、画面を最大化して実行
```

`logs/measurements/<時刻>.json` に、操作ごとの生のフレーム間隔・環境・判定が保存されます。

| 操作 | 判定の基準 | 合格の条件 |
|---|---|---|
| ワークスペースのドラッグ | PARAM-065（30 fps） | フレーム間隔の p50 ≤ 33.4 ms、かつ 66.7 ms を超えるフレームがない |
| ワークスペースのリサイズ | PARAM-065（30 fps） | 同上 |
| 画面の切り替え | PARAM-065（30 fps） | 同上 |
| 3D ビュー | KPI-5（60 fps） | p50 ≤ 16.7 ms、かつ 33.4 ms を超えるフレームがない（P-04 ⑥） |

報告の `evidence` が `NOT EVIDENCE` のとき（ヘッドレス、SwiftShader などのソフトウェア描画）は、達成の証拠にしません。

参考（証拠ではない）: 2026-11-09 に、この開発機のヘッドレスの Chromium（SwiftShader）・4K のビューポートで道具を動かしたところ、すべての操作で 1 秒あたり 2〜7 フレームでした。

## M-3. 実機のペンと複数指のタッチ（NFR-ENV-001）

| 端末 | 確認すること |
|---|---|
| ペン対応の Windows 端末（Surface など）・Edge | `/board` で、筆圧で線の太さが変わる、ペンの消しゴムボタンで消える、ペンを当てている間は手のひらが反応しない、2 本指でパン・ズーム |
| iPad・Safari | 同上（Apple Pencil）。画面へのインク（Alt+Shift+I の代わりに上部のボタン）で、プレゼンテーション中に書き込める |
| 共通 | 20,000 本のストロークを置いた状態（開発者ツールで `__basInk.seed(20000)`）で書き、遅れがないこと（NFR-PERF-004、16 ms） |

証跡は画面の録画です。結果は `docs/usability-results/<日付>-pen.md` に、端末・OS・ブラウザーの版と、項目ごとの合否を残します。
